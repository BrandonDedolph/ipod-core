## The specific things I was asked to look at

- **−1 unknown.** `jackwatch_feed` returns before touching `last` on any negative level (`ui/jackwatch.c:26-31`); `jackwatch_prime(−1)` is a no-op (`:68-70`). Tested (`unknown_never_primes`, `minus_one_mid_stream`, `prime_on_wake`), and the mutant that primes from −1 fails the suite. Correct.
- **Boot with an empty jack.** `run_ui` calls `jackwatch_reset(&g_jack)` before the loop (`kernel/main.c:5714`); nothing calls `hal_headphones_present()` before the loop (grep: only 5424 suspend, 5490 wake, 5874 loop). The HAL's first sample primes its debouncer and answers 0 at once; the module's first non-negative level primes `last=0` with NONE. No edge, no pause, no `core: jack out` line (`was` is −1 so the narration guard is false). Correct.
- **Wake re-prime.** `suspend_to_ram` samples once, primes, then reuses the same `hp` for the resume gate (`main.c:5490-5501`), unconditionally on `was_playing`. Pulled during sleep and left out: `last=0`, no resume, the first pass sees 0==0 — no phantom pause. Untouched: `last=1`, resumes if it was playing. Pulled *and re-inserted* during sleep: the wake sees `hp=1` and resumes if it was playing — indistinguishable from untouched, because the suspend loop only feeds the debouncer (`:5424`) and nothing records the intermediate 0. That is fine behaviour, but the plan's matrix, the hw doc and a test comment all claim "stays paused" for that case; see finding 7.
- **Unplug during the PLAY-hold window.** The jack block (`main.c:5863`) runs every pass, above the input switch where `keyhold_feed` lives (`:5935`). An unplug during the 2 s hold pauses via the module (`playing=1`); when the hold matures, `suspend_to_ram` computes `was_playing = player_active() && !player_paused()` = 0 (`:5219`), so the wake does not resume. Correct; constructed the case by reading both paths.
- **trusted=0 provably inert.** Consumers of `hal_headphones_present()`: `main.c:5424, 5490, 5874` — all three get −1 → prime no-op, resume-gate `!= 0` true (today's behaviour), feed NONE with `last` untouched. The narration guard `was >= 0` never fires. `paused_by`/`pauses` never move. `hw-headphone-untrusted` pins −1 with zero bus events across ten polls, then exactly one read for `headphone_raw()`, then `test_pin_cfg_grammar`. The only new per-pass traffic in the default image is the `headphone_raw()` read (`:5864`), plus two reads while About paints — exactly acceptance criterion 4.
- **Log budget.** `g_jack_raw_lines` is a BSS static (`main.c:770`), zero on every cold boot, never reset on suspend/wake (correct: "per boot"). The `>=` guard runs before the increment, so it saturates at 64 and cannot wrap; 63 raw lines + one "budget spent" notice = 64 lines. Docs say "64 lines per boot" — accurate.
- **About footer width and buffers.** Worst-case tokens: `adc[20]` holds `"ADC "`+10 digits+`" · "` (3 bytes for the UTF-8 middot) = 18+NUL; `jk[40]` holds `" · JACK 1/1 n65535 en=0 oe=1"` = 29+NUL; `w[24]` holds `"LOG 4294967295 err"` = 18+NUL; `v[80]` holds 18+18+29 = 65+NUL. Widths measured above; nothing reaches the 288 px drop threshold, let alone 320. The drop rule is mirrored in `render.py:1177-1179`.
- **Trace test pins zero writes.** `test_pin_cfg_grammar` first case: two `expect_r` then `trace_expect_end`, which asserts `cursor == mmio_mock_log_len()` (`tests/hw_mmio/trace_expect.h:85-94`) — any write to any address would be an extra event and fail. The six decode cases additionally check `mmio_mock_count(MMIO_OP_WRITE, …) == 0` on the two config registers. Yes, zero writes are pinned, in both non-probe binaries (`main()` at `:392` and `:441`).
- **Guide and hw doc vs code.** `JACK <raw> n<count>`, `/<debounced>` only when trusted, `en=0`/`oe=1` appended, ADC dropped first, 64-line budget, wake re-prime, log line names — all match `screen_settings.c:530-577` and `main.c:5863-5888`. ## Findings

1. **should-fix — `core/hal/hw/headphone.h:16-20, 54` — stale "transcript" wording contradicts the paragraph the branch added below it.** Lines 16-20 still read "Until the probe transcript has been seen, HEADPHONE_DETECT_TRUSTED stays 0 … Flip the three knobs below from the transcript, nothing else", and line 54 "0 until the probe transcript confirms line AND polarity". The new "WHICH PROBE" paragraph (`:22-30`) says a transcript can never be produced on this device and the About reading is what sets the knobs; the hw doc was rewritten to say "until one of the procedures above has been run" for exactly this reason. Also "three knobs": the plan and the bench edit two (`TRUSTED`, `ACTIVE_LOW`). Correct looks like: "until the pin has been read (About token, or the UART probe on a bench with a cable) … flip the two knobs below from that reading". Verified by reading the header; `tests/meson.build:698` has the same "device transcript" phrase.
2. **nit — `docs/screens/README.md:109` — the About caption is stale.** It lists the dashboard values "… ADC 2731, LOG 6 on)" but the regenerated `about.png` now ends `… · JACK 1 n0`. One clause. Read it.
3. **nit — `ui/jackwatch.h:53`, `ui/jackwatch.c:17,53,63,74` — `paused_by` has no consumer outside the module and its test.** Grep of the tree: nothing in `kernel/`, `player/` or `ui/` reads it. The plan's own definition ("until the next plug-in *or a resume elsewhere*") is unobservable from a module that never sees the transport's resume, so the field is bookkeeping that cannot yet mean what it says. Either say in the header that nothing reads it yet (it exists for a future "was this pause the jack's?" consumer), or drop it and the four lines that maintain it. Not a correctness issue.
4. **nit — `kernel/main.c:5872, 5882-5886` — a second edge detector in the file that is not host-built.** The narration re-derives "a debounced edge happened this pass" from `was`/`g_jack.last` instead of the module reporting it. It is correct as written (`last` only moves on a real edge after priming), but it is the one line of jack logic left in `main.c` that no test can see. The module could return `JACKWATCH_IN`/`JACKWATCH_OUT` alongside `PAUSE` and `main.c` would just print. Optional.
5. **nit — `kernel/main.c:3295-3297` — the `headphone_raw()` fallback in `settings_render_cur` is unreachable.** Commit d79692d's own message says About cannot paint before the loop's first sample (which resets and primes `raw_last`), so `g_jack.raw_last < 0` is never true here; the comment's "a paint that somehow precedes" hedges the same thing. Harmless (one extra read on a path that never runs), but it is code with a comment explaining a case that cannot occur. Either delete the ternary or make the comment say plainly that it is belt-and-braces.
6. **nit — plan acceptance criterion 3 not met literally.** `git diff --numstat` for `kernel/main.c` is +120/−30 = +90 net against "≤ ~40 lines net". The implementer flagged it; the excess is the `jack_narrate_raw` helper, the `_Static_assert`, and comment blocks, not policy. Noting for the record; no change requested.
7. **should-fix — `core/docs/hw/10-headphone-jack.md` ("Wake" paragraph) and `tests/ui/jackwatch_test.c:172-174` — "pulled and re-inserted during the sleep leaves it paused" is not what the code does.** With the plug back in at wake, `hp=1` and `was_playing` resumes (`main.c:5490-5501`) — identical to "wake without touching the plug", which is all the wake path can observe: the suspend loop keeps the debouncer fed (`:5424`) but no watcher records the intermediate 0. The doc sentence "A plug pulled and re-inserted during the sleep leaves it paused as well — no auto-resume, even there" and the test comment "The player stays paused (main.c's resume gate, not ours)" both repeat the plan's matrix row, which the plan itself contradicts one row later ("wake without touching the plug: resumes"). One sentence each: say it is indistinguishable from an untouched plug and resumes, or drop the claim. STATUS steps 14/15 and the guide's Sleep bullet only describe pull-and-stay-out and untouched, so they are fine. Constructed the case from the two code paths above.

- Commit messages explain why, in the house voice; the third commit is a small comment fixup, honestly labelled.
