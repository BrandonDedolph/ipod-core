## 1. Disk safety

**Write paths.** Two writers, both only ever call the injected `otg_write_fn` (main.c passes `ata_write_sectors`):

- `kernel/otg_store.c` — `run_at()` resolves every run fresh through `fat32_file_lba_at` (bounded chain walk, `next_cluster` validated per hop, EOC ⇒ `FAT32_ECORRUPT`), then refuses: `byte_off ≥ dirent size`, `byte_off ≥ 10240`, `base % ATA_PHYS_LOG`, `run < ATA_PHYS_LOG`, `base == 0 || base ≤ part_lba`, and clamps the run to what is left of the two-slot region. `*max_sectors` from `fat32_file_lba_at` is "what remains of THIS cluster", so a write cannot cross a run boundary; `slot_resolves()` proves every run of a slot before a byte is encoded, and `otg_store_save` re-resolves each run again immediately before each write. No FAT write, no directory write, no size change anywhere (read the whole file). The recorder in `otg_store_test` refuses any write outside the file's own clusters or crossing one; the fragmented fixture (slot 1 starts 1024 B into cluster 4) passes.
- `library/otg_slot.c` — `write_region()` does the same per-run resolve+checks, refuses `off ≥ size` or `bytes > size − off`, and every stage is a multiple of 1024 (stage 4096, file size checked ≥ 4096 and a multiple of 1024). The `otg_slot_test` recorder likewise refuses stray/crossing writes on a fragmented 20→40→21→41 target; the file bytes are asserted equal to an independently built expectation, padding included.

**Stage-0-last tear ordering.** `sink_put` writes stages ≥ 1 as they fill; `sink_finish` writes the partial tail then stage 0 (asserted by write order in the test: clusters [2],[3] first, then [0],[1]). I traced the tear cases by hand: (a) cut before stage 0 over an EMPTY target: old header `count=0` + old trailer at line 3 ⇒ if the new list spilled past 4096, `listed>0 ≠ 0` ⇒ damaged; if it did not spill, the file is byte-identical to the old empty form ⇒ still empty (correct, nothing lied). (b) cut mid-tail: same verdicts via count. (c) torn ERASE over a used slot: old header + new newline stages + old tail ⇒ `listed < count` or the old file intact ⇒ damaged or unchanged. The one case the gen/count test cannot see — a mixed file whose new and old lines have identical byte lengths — requires writing content over content, and Save never does that: `otg_slot_free_index` only offers `count == 0` slots (a fully padded file). So the implementer's deviation "a DAMAGED slot is not auto-reused by Save" is **load-bearing** for the tear argument, not just a UX choice — see finding S3, the docs still say the opposite.

**CRC coverage.** COREOTG.DAT: whole slot incl. header (seq) and padding; every flipped-bit position is tested in C, Python and Go. Slot file: entry lines only, host-checked (`--dump`, `ReadOTGSlotFile`), device uses gen+count as designed.

**`fat32_cache_drop`.** Two caches exist (`fat_cache`, `dat_cache`, each one FS-sector, tagged by `(fs, sector)`); nothing invalidated them before. The drop clears both flags for `fs` (or all for NULL); pinned in `fat32_test` (stale-then-fresh for data and for a re-pointed chain). `fs->read` on the device is `player_disk_read` → `ata_read_sectors` directly, no read-ahead layer underneath, so a read-after-write through `fat32_read_file`/the stream is coherent once the drop runs. Mid-playback cost: the pump's bulk reads bypass `dat_cache`; a drop costs at most one FAT-sector re-read at the next cluster hop and one data-sector re-read for a partial copy — no stall. `otg_store` reads raw and only at boot, so it needs no drop.

**Commit gate.** `otg_store_commit` copies the caller's env, overrides `writable` with its own, runs the real `cfg_commit_gate`, wakes on `WRITE_WAKE` before the write, and feeds `cfg_commit_result`. Pinned in `otg_store_test §6` with a hand clock: IDLE debounced (3 s) and never wakes parked; SOFT no debounce, never wakes; FORCE wakes first then writes; battery refuses IDLE/SOFT/FORCE (loud once, then quiet) but not LAST; three failures drop the change; not-writable drops the change and ignores the caller's `env.writable`. All six main.c sites gained one line (DISKSAFE LAST, standby FORCE, suspend FORCE, disk mode FORCE, Settings exit SOFT, idle). An add with the drive parked cannot wake it (gate rule, tested). Retry targets the same slot and leaves `seq`/`slot` untouched on failure (tested).

**Power cut between slots / stages.** COREOTG.DAT: one slot per save; a torn newer slot fails CRC and the older wins (tested); "unreadable + nothing valid ⇒ not writable" copied from config.c (tested). Slot file: covered above.

## 3. UI

**Row-Select arbitration.** `rowsel_arm` records `{scr, sub, sel, epoch}` at the down-edge and feeds `row_key` once at the event's tick; the per-pass block feeds live state every pass (so a release is always seen), drops the press when the screen/sub-state/epoch changes or Hold engages, and acts on TAP/HOLD only while pending. I checked the ISR: `s_btn_live = s.btn_map` is assigned *before* the down-edge is ORed into the latch in the same sampler pass, so on the pass that drains the event the live state already shows the press; a tap shorter than one pass correctly yields TAP on that pass. Only SONGS, PLAYLIST, OTG, BROWSER (both depths) and SEARCH-RESULTS arm; every other screen's Select is untouched (Settings sliders, theme picker, menus, Playlists list, Queue view, the charging/battery modal dismissal path — those zero `ev.buttons` and `keyhold_void(&row_key)` so a dismissing press is never pending). Now Playing's own `g_sel_down_us/g_sel_pending` block is not touched (tap = scrubber, hold = queue). Hold switch edge calls `rowsel_drop` and the live feed masks with `!g_locked`. Wake swallow voids `row_key` like `menu_key`. Search: `search_hold_rows()` returns 0 in PICK so the ring's Select stays a down-edge keystroke (`search_key`), and in RESULTS the tap path does what `SEARCH_ACT_OPEN` did (`search_open_hit`, np_first on a song). Wheel motion during a pending press does not cancel it and the recorded row acts (`g_song_sel = sel` etc.).

**Banner.** `otg_banner_render` → `top_banner_render` with the +/− ring, or a 1-row empty bitmap for a refusal; the render block polls both windows once, lock wins, `banner_up` replaces `lock_flashing`; the input drain disarms the OTG banner on the first button/wheel and falls through so the event is applied visibly. **Pinned row** at index 0 with the count; `g_pl_sel` offsets (`pi + 1` in `resume_open_playlist`, clamp in `playlists_load`, `playlists_row_count()` in the list table and `play_tap_start`). **SCR_OTG**: Clear is a two-press confirm on the row itself with a 3 s window that repaints when it lapses; Save picks the lowest `present && count == 0` slot, prints the first-Save LBA line once, writes under the load bar, re-points a playing OTG queue to `RESUME_KIND_PLAYLIST`/`name_hash("On-The-Go N")`, clears, binds, touches, SOFT-commits, rescans and lands the cursor on the new row; a save that wrote nothing keeps the live list. Hold on a track removes it with the index clamped. **Delete Playlist** row on a slot's tracklist survives the empty/damaged state so it is the way out. **Resume**: `RESUME_KIND_OTG = 7 = MAX`, ctx stored as 0 (resume_test), `resume_open_otg` checks the qidx hint then scans by song, falls back to the album when the list is empty (cleared) or no longer holds the song; `resume_capture` unchanged. Clear under a playing OTG queue leaves the player's copy alone (correct per plan).

## Findings

### Blocker

**B1 — `core/kernel/main.c:3379-3385` (`playlist_open`): a FOREIGN file at a slot name gets the Delete Playlist row, and Delete (`otg_delete_slot`, main.c:5186) would overwrite the user's own playlist.**
`g_pl_slot = otg_slot_index(g_playlists[pi].name)` is set from the name alone; when `otg_slot_verify` reports `info.present == 0` (no `#CORE-OTG` directive — the user's own "On-The-Go 2.m3u8"), `g_pl_slot` stays > 0. So `playlist_row_count()` adds the Delete row, `playlist_row_draw` draws it, and `row_select_tap` → `otg_delete_slot` → `otg_slot_save(... 0 rows ...)` writes the empty form over the user's file whenever its size happens to be ≥ 4096 and a multiple of 1024 (otherwise the writer refuses and the user sees "Could not delete" on a row that should not exist). The plan (§6 and Risks: "the device treats a directive-less file as a plain playlist (listed, playable, never written to — Save skips a foreign slot, as does Delete)") and `core/docs/design/on-the-go.md`'s table ("foreign … never writes to it") both promise the opposite; `core doctor`'s own message says "the device … never writes to it". Save is correct (`otg_slot_free_index` requires `present`); only Delete is wrong. Correct: zero `g_pl_slot` when `!info.present` (and decide explicitly what an unreadable file, `g_pl_err != 0`, should do — today it also keeps the row and skips the verify). Verified by reading `playlist_open`, `playlist_row_count`, `row_select_tap` and `otg_delete_slot`; the destructive case is rare because of the size gate, but it is a reachable path that destroys user data in the branch whose whole discipline is "never touch a file the user made".

### Should-fix

**S1 — `core/docs/design/on-the-go.md:3-13`: the status header is stale (still at a26e9ef).** It says "storage half implemented, UI pending … nothing in `kernel/main.c` calls them yet, so the feature is invisible on the device … documented in `docs/USER_GUIDE.md` when it lands." Commit 3 landed the UI and the guide section (the rebase touched a sentence lower in this file and left the header). The doc is named as the format reference from STATUS, core/README and tools/README, so its first paragraph must not contradict them.

**S2 — `CHANGELOG.md`: two `## Unreleased` headings** (line 6, main's Search/A–Z/MP3/etc.; line 71, On-The-Go). The rebase should have put the three On-The-Go bullets under the existing Unreleased section. The implementer's "CHANGELOG Unreleased heading" note reads as if one was added, not duplicated.

**S3 — "a damaged slot counts as FREE for the next Save" is still stated in four places but the code does not do it.** `otg_slot_free_index` (main.c:3869) offers only `present && count == 0`; a damaged slot has `count > 0` and is never offered — recovery is Delete, as the implementer's deviation says. Still saying "free": `core/library/otg_slot.h:65`, `core/docs/design/on-the-go.md:175` and the state table's `damaged | … | free`, `tools/make_otg.py:446` (`_dump_slot_playlist`: "treats the slot as free") and `core/cli/internal/doctor/doctor.go:542` (`checkPlaylists`: "treats the slot as free"). This is not cosmetic: as traced in §1, Save never writing over content is what closes the one tear the gen/count test cannot see, so the design doc should state the rule as it is (damaged ⇒ not free; Delete rewrites it whole) and why.

**S4 — Plan acceptance criterion 5 not recorded.** The plan says the `--verify` LBAs vs the C formula are "compared by hand on the image once and recorded in `STATUS.md`". Nothing in STATUS records it. I did the comparison (table above: 0x4C/0x52 on the fragmented chain, run structure identical); a line in the STATUS entry saying it was done, on what geometry, closes the criterion.

### Nits

**N1 — `core/kernel/main.c` `otg_row_draw`: dead greying.** The Clear row is greyed on `g_otg.n == 0` and Save on `(g_otg.n == 0) || …`, but `otg_render` returns before drawing any row when `n == 0` and `list_view_current` returns 0 for that state, so the `n == 0` branches never execute. The plan, `render.py`'s `screen_otg` and the guide ("two rows at the top, then the tracks") describe the two rows as present-but-greyed on an empty list; the device shows only the two sentences. Either draw them greyed or delete the dead conditions and say so in the comment.

**N2 — `tools/make_otg.py`:** `do_verify` line 680 has `return 1 if rc else 1` (always 1; write `return 1`). `parse_slot_playlist` parses count/gen with `int(s, 10)`, which accepts `+0012` and ` 0012`; the device's `parse_dec` and Go's `parseDecN` reject them, so the reference oracle is laxer than the two implementations it is the oracle for.

**N3 — `core/library/otg_slot.h:227-230`** says a part-way write failure leaves a file that "is DAMAGED by construction, which is exactly what the next reader will say". True for a failure before stage 0; a failure *inside* the stage-0 run can leave a header-less first sector, which classifies as FOREIGN (listed, played, and never written again until a host sync). Rare (drive write failure mid-run) and `core doctor` would report it, but the comment overstates.

**N4 — STATUS.md:** the plan asked for items in the "First-flash checklist" section (line 854) and a dated entry; the nine-step bench lives only inside the (undated) entry. Fine as a bench list; just not where the plan put it.

### Confirmed correct despite looking suspicious

- Same-pass `rowsel_arm` feed + live feed: safe, the ISR updates `s_btn_live` before latching the edge.
- `g_list_epoch` is bumped by `scr_push/pop`, `playlists_load`, `playlist_open`, `songview_build`, etc., not by wheel motion — a pending press survives a thumb rock and dies on a rebuild, as designed.
- `otg_bind_all()` at `library_ensure`'s tail runs at boot before `otg_store_mount` (harmless on an empty list) and is called again explicitly after the mount.
- `otg_store_mount` decodes the winning slot with `otg_slot_decode`, which `otg_init`s first, so a later, newer slot cannot leave a half-filled list.
- `env.writable` handed to `otg_store_commit` is deliberately ignored; tested.
- `resume_qidx` is a u16 hint, bounds-checked before the array read.
